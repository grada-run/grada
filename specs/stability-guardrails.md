# Specification: Agentic Guardrails, State Audit, and Migrations

## 1. Overview
This sprint focuses on platform bulletproofing and proactive AI assistance. It hardens state transitions against invalid topologies by implementing a unified dispatch pattern, programs the IDE AI agents to proactively enforce infrastructure guardrails via the rule generator, and completely revamps the platform migration guides in the Astro Starlight docs to reflect the modern compute targets.

## 2. Boundaries & Constraints
- **Target Isolation:** Commands like `sleep`, `wake`, and `exec` must use a unified, early guard helper to exit gracefully (or fail cleanly) on unsupported targets before executing any AWS calls or side effects.
- **FinOps Preservation:** If a `--target lambda` project has a provisioned database (`findDbTarget` is true), `sleep` and `wake` MUST still execute to hibernate/restore the RDS cluster. The intercept only applies if no DB exists.
- **Single Source of Truth:** AI rules must be generated by `src/utils/ai-rules.js` and synced to the dogfood repo; hand-maintained dotfiles must not drift.

## 3. Implementation Targets

### A. Edge-Case & State Transition Audit
Audit the core lifecycle commands and refactor target dispatch.
- **Target Vocabulary Unification (R2):** Unify `COMPUTE_TARGETS` across the codebase (including `src/utils/resolvers.js`) to export `['ecs', 'lambda', 'static']`.
- **Early Guard Refactoring (R1 & R3):** Create a shared guard helper in `src/utils/resolvers.js` that checks the target *before* prompting or making AWS calls. Migrate `sleep`, `wake`, `exec`, `rollback`, and `logs` to use this dispatcher.
- **`sleep` & `wake` Rules:** 
  - `static`: Intercept and exit cleanly.
  - `lambda`: Intercept and exit cleanly ONLY IF no database is provisioned. Otherwise, continue to the RDS hibernation logic.
  - Update `tests/sleep-wake.test.js` and add `exec-static` / `wake-static` coverage.
- **`exec` Rules:** Intercept `static` and `lambda` targets early and fail with an educational message ("ECS Exec is not supported on Lambda or Static targets").
- **Add-on Injection Safety:** Add a warning in `src/commands/add.js` if a user adds `queue:sqs` to a `lambda` or `static` target, noting that long-running workers require ECS.

### B. Automated IDE Guardrail Hooks
Upgrade the AI Rule Generator (`src/utils/ai-rules.js`) to transition the AI into a proactive pair programmer.
- **Target-Aware Architecture (R5):** Update `aiContext` in `init.js` and `sync-ai.js` to include the compute target. Modify the generator so it stops hardcoding "ECS Fargate + ALB" and instead describes the actual detected target topology.
- **Trigger Rules:** Add these explicit rules to the base rule text (fanning out to `grada.mdc`, `.windsurfrules`, `.github/copilot-instructions.md`, etc.):
  1. **Terraform Validation:** "When you modify any `.tf` file, you MUST automatically run `terraform validate` to ensure syntax correctness."
  2. **Secrets Management:** "When the user asks you to add an environment variable, or you modify `.env`, you MUST explicitly remind the user to run `npx grada-run secrets audit` and then `secrets push` to sync the secret to AWS."
  3. **Infrastructure Sync:** "If you modify a `package.json` build script or framework output directory, remind the user to run `npx grada-run apply` if the infrastructure needs to be updated."
- **Dogfood Sync (R4):** Dogfood the repo by syncing these generated rules back into the Grada repository itself and pinning them with a regression test.

### C. Migration Guide Deep Review
Rewrite the Starlight documentation in `apps/docs/src/content/docs/migrations/` to guide users migrating from competing PaaS providers to the new target matrix.
- **`astro-vercel-to-aws.md`, `nextjs-vercel-to-aws.md`, `sveltekit-vercel-to-aws.md`:** Rewrite these to explicitly map Vercel Serverless Functions to `--target lambda`, Vercel Static Exports to `--target static`, and Vercel KV/Postgres to `db:redis` / `aurora-postgresql`.
- **`heroku-procfile-to-aws.md`:** Map Heroku Web/Worker Dynos to `--target ecs` and `queue:sqs`. Cover how to migrate Heroku Postgres using `grada db import`.
- **`docker-compose.md` (Extension):** Extend the existing guide (`guides/docker-compose.md`) to explicitly cover sidecar handling and Lambda/static equivalencies.
- **Migration Index (R6):** Create a new `migrations/index.md` page with a cross-linked matrix mapping source providers (Vercel, Heroku) to Grada compute targets.

## 4. Acceptance Criteria
1. Running `grada sleep` on a `--target static` (or a `lambda` with no DB) exits gracefully before AWS calls.
2. The `exec` command throws a clean capability error on `static`/`lambda` targets.
3. `src/utils/ai-rules.js` generates the 3 new trigger rules and dynamic architecture contexts for all 9+ supported agents.
4. The migration docs in `apps/docs/src/content/docs/migrations/` map competitor concepts to the new target matrix.
