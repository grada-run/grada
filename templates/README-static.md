## 🏗️ Architecture Overview

Your static site is hosted without any always-on compute:

* **Storage:** Your `{{BUILD_DIR}}/` build output syncs to a **private S3 bucket** (public access fully blocked, encrypted at rest).
* **CDN:** A **CloudFront distribution** (`PriceClass_100`) serves the bucket worldwide over HTTPS. It reads through an **Origin Access Control (OAC)** — the bucket is never publicly reachable.
* **Routing:** Unknown paths fall back to `/index.html`, so client-side routers (React Router, Vue Router, SvelteKit SPA mode) work on refresh and deep links.
* **Security:** Deployments run via GitHub Actions using **AWS IAM OIDC** — no long-lived AWS keys stored anywhere.
* **State Management:** Terraform state is securely backed by an encrypted S3 bucket with native S3 locking.

### ⚠️ Troubleshooting: OIDC Provider Already Exists
If `terraform apply` fails with `EntityAlreadyExists` for the OIDC provider, this AWS account already has a GitHub Actions provider (AWS permits one per account). Set `create_oidc_provider` to `false` in `terraform/oidc.tf`:
```hcl
variable "create_oidc_provider" {
  type    = bool
  default = false # <--- Change this from true to false
}
```
Re-run `npx grada-run apply` to link directly to your existing provider.

### ⚠️ Troubleshooting: Blank Page After Deploy
If the CloudFront URL serves a blank page, your framework likely emitted a different output folder than `{{BUILD_DIR}}/`. Check your build log, update the `BUILD_DIR` env var in `.github/workflows/deploy.yml`, and re-push. If your framework emits `build/` or `out/`, that is the usual culprit.
